Agent 开始替你干活，文件工具该怎么配合？

出品：王福强 · 把文件这件事儿，理顺！

AI 把资料写好了，人还得负责搬。

设想你让一个能调用工具、执行任务的 AI 助手，也就是 Agent，整理了一份客户背景、一张问题清单和一份沟通提纲。几个文件都在电脑上的“客户沟通准备”目录里。

第二天换台电脑出门，才想起来资料还在昨天那台上。于是压缩、发送、下载、解压。路上改了两段，回来又得确认哪份更新。

前面的任务自动做了，后面的接续还在手工折腾。

我们觉得，面向 Agent 和 AI Native 时代的文件工具，要认真处理这一段。助手产出的东西，总得在下一台电脑、下一次会议里继续用。

顺手把目录加入同步

FooCloud(https://keevol.cn#foocloud) 已有一个具体的 MCP 接口：把电脑上已经存在的目录加入同步。MCP 可以简单理解为让 AI 助手调用软件能力的一种约定。

前面的任务就能多接一句：

把刚才生成的“客户沟通准备”目录，加入 FooCloud 同步。

使用支持该接口、已完成配置的 Agent，FooCloud 桌面端也已登录，就可以发起这个请求。文件夹需要授权，或者云端已有同名目录时，仍然要由你确认。

目录接入以后，还要等里面的文件同步。“加入成功”和“已经传完”，是两个状态。 出门前要看的，是文件是否已经传完；另一台电脑也得连接同一个可访问的服务，取得相应目录。

如果 Agent 原本就把产出放在同步目录里，继续在那里做就行，没必要每次重新接入。

这个入口更适合另一种情况：不同项目、不同工具把资料放在不同位置，你想让目录留在原处，也能纳入同步。过去需要找目录、再添加的动作，就有机会顺着任务一起完成。

少一次切换，少一次搬运，价值就在这些地方。

生成得越多，越得考虑以后怎么找

助手写得快，文件也会越积越多。过一阵子，你可能记得内容，却忘了名字。

比如“渠道试点”这个词，出现在某份会议记录正文里，文件名却只是日期。FooCloud 现有的本地内容关键词搜索，可以从已纳入索引、能够提取文字的本地文件里找线索，再打开原文确认。

范围要讲清楚：没有进入本地索引的云端资料、无法提取文字的扫描图片，不能默认已经能搜到。

再往前走，就会碰到另一类要求：连原文的词也记不准，只知道想找什么。

上次那份建议先选两个客户试一试、不要立刻全面推广的材料，在哪里？

原文可能写的是“小范围验证”或“分阶段上线”，和提问没几个相同的词。这时候，就需要理解意思。

FooCloud 计划实现 AI 语义搜索，目前尚未开放为可用功能。我们会根据天使客户的真实任务确定优先级，快速开发需要的能力。

具体先解决什么，值得听使用者的。销售想找相似项目的建议，写方案的人想找曾经讨论过的取舍，都叫“AI 搜索”，要验证的任务却不一样。

带着一个真实提问、一组可验证的样例，以及“找到哪份才算找对”的判断来交流，比泛泛地说更智能，更容易推进。

接得上什么，就看具体动作

Dropbox Dash 的 MCP 接口提供了搜索、读取文档等工具。行业已经在把文件能力接给助手使用，但不同产品交出来的动作并不一样。

FooCloud 当前 MCP 集中在“把已有本地目录加入同步”，没有提供 MCP 搜索或读取远端文件的工具。前面的关键词搜索，仍由人在 FooCloud 中使用；语义搜索是后续方向。

选型时，把自己的一段工作拿出来对照就好：助手负责哪一步，FooCloud 接哪一步，哪里还需要确认。贴上 AI Native 标签很容易，接续过程中少几次手工操作，才是使用者能感受到的变化。

也要了解所用 Agent 的配置与数据处理方式。MCP 在本地接入目录，并不能据此推断外部助手或模型不会把其他数据发出去。

拿一个小目录跑通

可以按自部署试用说明准备环境，原文沿用了 FSCloud 旧名。如果环境由同事负责，让他提供两台设备都能访问的服务即可。

选一组不含敏感信息的项目样例，确认客户端版本和 Agent 配置支持这个入口，再依次检查：目录是否按意愿接入，首轮同步是否完成，另一台能否取得正确文件，之后能否用正文关键词找回一份资料。

实际结果记进试用清单。卡在搬运，就说清卡在哪一步；卡在查找，就留下当时怎样问、希望找到什么。

AI 帮你做完的工作，下一次还能接着用。我们想围绕这件事，把文件工具继续做下去。
